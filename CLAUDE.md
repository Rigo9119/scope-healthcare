## Commands

**Frontend (root)**
```bash
bun --bun run dev          # dev server on :3000
bun --bun run build        # production build
bun --bun run test         # run tests with vitest
bun --bun run check        # lint + format check (biome)
bun --bun run lint         # lint only
bun --bun run format       # format only
bun --bun run generate-routes  # regenerate src/routeTree.gen.ts
bun --bun run machine-translate  # auto-translate messages via inlang
```

**Sanity Studio (studio/)**
```bash
cd studio && bun --bun run dev    # run studio locally
cd studio && bun --bun run deploy # deploy studio to Sanity hosting
```

## Architecture

This is a **React SPA** (TanStack Router) backed by **Sanity CMS**, deployed on Netlify. The repo has two independent packages:

- `/` — Frontend (Vite + React 19 + TanStack Router + Tailwind CSS v4)
- `/studio` — Sanity Studio v3 (separate `package.json`, separate `node_modules`)

### Data flow

Content is fetched at runtime from Sanity (project `3fyb50d2`, dataset `production`) via `src/lib/sanity.ts`. Every page component loads Sanity data and falls back to the inline `FALLBACK` constant if the fetch fails or returns null. GROQ queries live in `src/lib/queries.ts`.

### Routing

File-based routing via TanStack Router. Add route files under `src/routes/`. **Never edit `src/routeTree.gen.ts`** — it is auto-generated by `tsr generate` (runs via vite plugin on dev, or manually with `generate-routes`).

### i18n (two-layer)

**UI strings** (nav labels, static copy): Paraglide JS via inlang.
- Source files: `messages/es.json` (base) and `messages/en.json`
- Generated output: `src/paraglide/` — **do not edit these files**
- Usage: `import { m } from '#/paraglide/messages.js'` → `m.key_name()`
- Base locale is `es`. Add new keys to both JSON files.

**Page content** (hero, specialties, testimonials, etc.): Sanity document-internationalization plugin.
- Documents follow the ID convention `homePage-{locale}` (e.g. `homePage-es`, `homePage-en`)
- The `useLang()` hook (from `src/i18n.tsx`) exposes `locale` and `switchLocale`; pass `locale` to `fetchHomePage(locale)` to load the correct Sanity document

### Sanity Studio structure

Schemas live in `studio/schemaTypes/` split by type:
- `documents/` — top-level document types (currently just `homePage`)
- `objects/` — reusable embedded types (`hero`, `statItem`, `specialtyItem`, etc.)

Studio uses a custom structure (`studio/structure/index.ts`) that surfaces one `homePage` editor per locale instead of a generic document list.

### Design system

All design tokens are defined in `src/styles.css` inside `@theme {}` (Tailwind v4 convention). Key decisions:
- **Primary color**: navy blue, `--color-primary-500: #1059b5`
- **Headings**: `font-heading` → Poppins; **Body**: `font-body` → Open Sans
- **Shape language**: sharp corners (no border-radius) throughout UI
- **Semantic tokens**: use `text-text-primary`, `bg-bg-page`, `border-border-default`, etc. rather than raw neutrals
- **Button shadows**: named shadow tokens (`shadow-btn-primary`, `shadow-btn-white`, etc.)
- `.link-animated` utility class in `src/styles.css` for underline-on-hover nav links

### Icon mapping

Lucide icons are mapped by string name in `src/routes/index.tsx` via `ICON_MAP` / `resolveIcon()`. When adding new icon references in Sanity content, add the corresponding import and entry to `ICON_MAP`.

### Path alias

`#/` resolves to `./src/` in both Vite and Vitest configs.

## Development practices

### Mobile-first
Write styles mobile-first: base classes target small screens, then layer `sm:`, `md:`, `lg:` overrides. Never write desktop styles first and try to undo them at small breakpoints.

### Language
All copy defaults to **Spanish**. Write Spanish labels, CTAs, section headings, and nav from the start. English is only needed for `messages/en.json` (i18n mirror) or foreign-patient testimonials.

### Content before routes
Lock in design tokens and refine existing pages before adding new routes. Don't scaffold new routes until the current page's design is approved.

### Aesthetic — clinical, not SaaS
The brand is a medical tourism clinic: light, bright, calm, trustworthy. Avoid dark navy full-bleed backgrounds, neon glows, glassmorphism (`bg-white/5`), grid/dot backdrops, and SaaS product widgets. Prefer white + `primary-50` surfaces, soft shadows, real medical content (specialties grid, care-journey steps, trust signals, contact bar).

### Hero sections
Avoid large empty dead space. Use split 2-column layouts (text left, visual/social-proof right) or fill the viewport with enough content. A centered single-column hero with `min-h-screen` and little content will leave ~60% dead space.

### Gradients
For gradient-heavy elements, use inline `style={{ background: 'linear-gradient(...)' }}` with explicit hex values instead of Tailwind gradient utilities at the 800–950 range (they render near-black).

## Linting & formatting

Biome (not ESLint/Prettier) for the frontend. Config in `biome.json`:
- Indent: **tabs**
- Quotes: **double**
- `src/routeTree.gen.ts` and `src/styles.css` are excluded from Biome

The Studio uses its own ESLint + Prettier config (single quotes, no semis).
